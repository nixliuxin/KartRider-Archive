# 跑跑档案馆是怎么托管的

kartarchive.com 背后有约 5 GB 的模型和贴图，但打开它只需要一个浏览器标签页，不用安装任何东西。整个网站只用一个 Cloudflare Workers 和一个 Cloudflare R2 存储桶，打开什么才加载什么；同时，搜索引擎和大模型问答工具在每种语言下都能读到一个完整的页面。

---

## 一个函数加一个存储桶

Cloudflare Workers 负责网站本身：网页、脚本和界面图片。Cloudflare R2 存储桶放档案的内容，约 9.2 万个文件，包括模型、贴图、动画数据和卡片图，静态资源放不下这么多。除此之外没有别的服务器。网站只在自己的域名上应答，`www` 跳转到主域名。

## 打开什么才加载什么

页面先加载一份全部卡片的索引。打开一张卡片时，才去取它的模型、贴图和动画数据；每个文件在使用前都要和索引里记的校验值核对一遍。数据文件每次访问都会重新验证，档案馆更新后，下次打开就是新版本。

## 不跑脚本也能读

三维车库需要脚本和 WebGL，但很多读者两样都不跑，包括大多数大模型问答工具。所以网站另外提供几种纯文本页面：

- `/catalog/`：一个不含脚本、不含图片的页面，列出全部卡片，以及游戏给每张卡片起的各语言名称。每个名称都链接到 `/?item=<id>`，点开就在车库里打开这张卡片。
- `/llms.txt` 给大模型介绍这个网站，`/llms-full.txt` 是完整目录的纯文本版。
- `/sitemap.xml` 列出四种语言的首页和目录页，`robots.txt` 对所有爬虫开放。

这些文件和页头都由生成器从网站自己的数据写出，名称和数量不会和车库里显示的对不上。只要有一份过期，测试就不通过。

## 每种语言同一个地址

`/` 是简体中文，因为档案来自国服客户端。`?lang=zh-TW`、`?lang=en`、`?lang=ko` 分别是繁体中文、英文和韩文。这三种语言的页面，由 Cloudflare Workers 在边缘节点用 `HTMLRewriter` 改写后再发出：语言属性、标题、描述、规范链接、社交分享标签、结构化数据和不跑脚本时显示的文字都换成对应语言。不跑脚本的爬虫也能拿到正确的语言。

改写过的页面不带 `ETag` 和 `Last-Modified`，请求里的条件头也会被去掉，这样缓存的某一种语言永远不会被确认成另一种语言。

在浏览器里，网站先看 `?lang=`，再看访客上次的选择，最后才用简体中文，不跟随浏览器语言。原因是谷歌用英文浏览器渲染页面，而首页声明的是简体中文，跟随浏览器语言会让两者对不上。

## 每次上传前后都核对

上传前，同一份 Cloudflare Workers 代码在本地对着整理好的数据副本运行，网站先在本地检查一遍。上传后，把存储桶整个读回来，和本地副本逐个比对：每个文件都要在、大小一样，也不能多出任何文件。
